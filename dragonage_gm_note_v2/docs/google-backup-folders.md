# GM-note 카테고리 폴더와 최근 3일 변경 이력

## 보관 범위

- 서비스 이미지 폴더: 캐릭터 / NPC / 갤러리 / 게시글 / 댓글 / 기타. 사용 중인 원본은 기간과 관계없이 유지합니다.
- 비공개 백업의 assets: 카테고리별 이미지·첨부 원본과 경로·체크섬 대응표. 날짜 정리 대상이 아닙니다.
- 비공개 백업의 latest: 카테고리별 최신 암호화 행과 삭제 표시. 수정한 지 오래된 행도 보존합니다.
- 비공개 백업의 records: YYYY-MM-DD / 카테고리 안에 이전 버전. 한국시간 오늘·어제·그제만 보관하고 더 오래된 관리 대상 변경 이력을 휴지통으로 보냅니다.
- snapshots와 별도의 전체 이관 보관본: 복구 기준본이므로 자동 정리하지 않습니다. 주기적인 전체 DB 덤프를 새로 만드는 기능은 이번 변경에 포함되지 않습니다.

공개 서비스 이미지와 개인정보가 담긴 비공개 백업은 서로 다른 기존 루트 폴더를 유지합니다. 원본 링크·파일 ID, DB 데이터, 로그인·권한은 변경하지 않습니다. Google Sheets의 최신 데이터 탭도 유지하고 변경이력 탭만 기간에 맞게 정리합니다. 휴지통을 자동으로 비우거나 파일을 영구 삭제하지 않습니다.

## 적용

1. 기존 Apps Script 프로젝트 GM-note Image Storage를 엽니다. 로컬 google-apps-script/Code.gs, Backup.gs, Organization.gs를 각각 같은 이름의 파일에 반영합니다. 기존 Code.gs 하나에 모든 코드가 들어 있다면 data/drive-diagnostics/Code-with-backup.gs의 전체 내용으로 그 파일을 교체할 수도 있습니다. 같은 상수·함수가 중복 정의된 다른 파일을 함께 두지 마세요. Script Properties의 기존 비밀값과 폴더 ID는 유지합니다.
2. 저장 후 함수 선택에서 setupOrganizedBackups를 한 번 실행합니다. 이 함수가 10분 간격의 maintainGoogleBackups 트리거를 만들고 초기 최신 사본 색인을 확보합니다. 기존 자료는 한 번에 최대 100건씩 처리하므로 초기 정리 완료까지 여러 차례 실행될 수 있습니다. 최신 사본 확보 전에는 오래된 이력을 삭제하지 않습니다.
3. 배포 → 배포 관리 → 기존 웹 앱의 수정(연필) → 새 버전 → 배포. 기존 배포 ID와 /exec 주소를 유지합니다.
4. 사이트의 Drive 업로드 헬퍼 변경도 함께 배포해야 신규 이미지가 올바른 카테고리로 분류됩니다. 비밀값은 프런트엔드에 전달하지 않습니다.

기존 암호화 인증 기록 중 현재 행을 판단할 수 없는 자료나 알 수 없는 수동 파일은 안전하게 기존보관으로 남깁니다. 자동으로 지우지 않습니다. 다른 프로젝트의 파일은 이 정리 작업 대상이 아닙니다.

## 검증 및 복구

공개 /exec의 organizationVersion이 gm-organized-2026-11-16이면 새 코드가 배포된 것입니다. 시간 트리거 목록에서 maintainGoogleBackups를 확인하고 실행 로그의 bootstrap 진행·이동 건수·정리 건수를 확인하세요. 초기 정리가 끝난 뒤 Drive에서 latest와 records/YYYY-MM-DD/카테고리, assets/카테고리를 확인합니다.

복구 도구 backup/google/recover.mjs는 폴더 하위를 재귀적으로 읽습니다. 백업 루트에서 events 모드를 실행하면 latest와 records를 함께 읽고 최신 행·삭제 표시를 재구성합니다. assets 모드는 assets의 카테고리 하위 매니페스트까지 검증합니다. 자동으로 운영 DB에 복원하지 않습니다.

현재 적용 상태: 로컬 코드와 테스트를 준비했습니다. 실제 Apps Script 배포 및 시간 트리거 생성은 서버에서 별도로 확인해야 합니다.
