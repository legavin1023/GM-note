# Discord 알림: 팀 작품 게시판

이 스크립트는 `team_art_posts`를 60초마다 Supabase 공식 API로 조회하고, 새 글을 Discord 웹훅에 순서대로 보냅니다. 테이블의 기존 RLS를 그대로 적용하므로, 전용 Supabase Auth 계정이 로그인 후 해당 게시판을 읽을 수 있어야 합니다. 로그인이나 RLS를 우회하지 않습니다.

## 설정

1. 비밀번호 로그인과 게시판 읽기 권한이 있는 전용 Supabase Auth 계정을 준비합니다. 해당 계정으로 앱에서 팀 작품 게시판을 실제로 읽을 수 있는지 먼저 확인합니다.
2. 저장소 루트의 `.env.example`을 참고해 `.env`를 만들고 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `BOARD_BOT_EMAIL`, `BOARD_BOT_PASSWORD`, `DISCORD_WEBHOOK_URL`, `SITE_URL`을 채웁니다. 실제 웹훅 주소는 `.env`에만 두며 저장소에 커밋하지 마세요.
3. `BOARD_PATH`는 기본값 `/GM-note/#/board/free`이며, `SITE_URL`은 사이트 도메인만 지정합니다. 게시글 링크에는 앱에서 해당 글을 강조 표시하는 `postId`가 붙습니다.
4. 필요하면 `BOARD_POLL_INTERVAL_MS`를 밀리초 단위로 지정합니다. 기본은 60000입니다.
5. 실행: `npm run discord:watch-board` (Node.js 18 이상).

최초 실행에서는 가장 최근 글의 `created_at`을 기준점으로 저장하고 기존 글을 알리지 않습니다. 이후 기준점보다 새로운 글을 오래된 순서부터 보냅니다. 성공 전송 ID는 `data/discord-board-watcher-state.json`에 기록되며 재시작 후에도 유지됩니다. 이 상태 파일을 삭제하면 기존 글이 다시 기준점 처리되므로 알림이 재초기화됩니다.

작품 게시판 스키마에는 별도 제목 필드가 없어 본문 첫 줄을 제목으로 사용하고, 본문이 비어 있으면 이미지 게시글 제목을 표시합니다. Discord 제한 응답(429)의 재시도 대기를 따르며, 네트워크·서버 오류에는 지수형 재시도를 합니다. 한 글 전송이 끝내 실패하면 그 글 ID는 저장하지 않고 다음 조회에서 다시 시도합니다.

Discord 전송 성공 직후 상태 파일 기록 전에 프로세스가 강제 종료되는 아주 짧은 구간에는 같은 글이 재전송될 수 있습니다. 외부 웹훅 전송과 로컬 파일 저장은 단일 원자 작업이 아니기 때문에 가능한 장애 구간입니다.
